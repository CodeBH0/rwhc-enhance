# rwhc v2026.09.22

Released 2026-09-22 · [full changelog](https://github.com/CodeBH0/rwhc-enhance/blob/master/CHANGELOG.md) · [中文更新日志](https://github.com/CodeBH0/rwhc-enhance/blob/master/CHANGELOG_zh.md) · previous release: [`v2026.09.02`](https://github.com/CodeBH0/rwhc-enhance/releases/tag/v2026.09.02)

Windows 11 HDR calibration tool. Unzip the attached `rwhc-v2026.09.22.zip`, then
`pip install -r requirements.txt` and `python app.py` — see the
[README](https://github.com/CodeBH0/rwhc-enhance/blob/master/README.md) for the full setup.

## Highlights since v2026.09.02

### Added

- **CLUT (multi-dimensional LUT) ICC output** (`clut_icc.py`). The generated profile can now
  additionally carry the standard ICC v4 lookup tables — `A2B0` (device PQ code → PCS) and
  `B2A0` (PCS → device PQ code) as `lut16Type`/`mft2`. Grid selectable 17/25/33/37/45/65
  (default 33), new checkbox **"CLUT (A2B0/B2A0)"**, off by default. Purely additive: the
  matrix tags and `MHC2` are left intact, and the CLUT is derived only from data this
  calibration already measured (no extra measurement).
- **Historical colour data** (`color_history.py`) — the counterpart of the existing
  "Historical gray data": reuse a past calibration's colour measurements (parsed from
  `hc.log`, offered only when a run is complete) instead of re-measuring them. New dropdown
  + "Refresh", next to the grey one.
- **Calibration with no colorimeter connected.** When both history dropdowns point at past
  measurements, the instrument, the `dogegen` pattern generator and the "place the
  colorimeter" dialog are not started, and the redundant post-calibration gamut
  re-measurement is skipped. `Measure color accuracy` now says it needs a real instrument
  instead of failing with a traceback.
- New self-check tools that need no display and no colorimeter: `tools/verify_lut_inverse.py`
  (36 checks), `tools/verify_clut_profile.py` (25), `tools/verify_clut_app_integration.py`
  (13), `tools/verify_color_history.py` (40).

### Fixed / improved

- **"Save ICC file" no longer freezes the window.** With the CLUT enabled, the `B2A0`
  inverse solve used to run synchronously on the Tk main thread — measured 17³ ≈ 5 s,
  25³ ≈ 17 s, 33³ ≈ 37 s, and minutes at 45³/65³, during which the window did not repaint.
  The tag computation now runs on a worker thread: the main loop is blocked for at most
  **0.21 s** while saving a 33³ CLUT, and the resulting profile is **byte-identical**
  (same sha256) to the one the synchronous path produced.
- **CLUT inverse solve ~1.6× faster** (`clut_icc.DisplayModel._candidate_devices`): the first
  nearest-neighbour stage now uses the mathematically identical norm expansion
  `|a|² − 2·a·b + |b|²` (one BLAS matrix multiply) instead of a full difference array that
  was an ~8.6 GB-scale round of temporaries at 33³. Output is unchanged to the last bit
  (verified `max|Δ| = 1.1e-16`), and a latent reshape bug that only worked for
  `per_row × refine_grid³` call sizes is fixed.
- **The `MHC2` 1D LUT is now built by a real inverse of the measured PQ response**
  (`lut.generate_mhc2_lut_from_measured_pq()`): nearest-neighbour lookup → piecewise-linear
  inverse (`np.interp`). Be aware of the honest scope: measured over all 15 real grayscale
  runs in `hc.log`, the old and new LUTs differ by **mean 0.006 / max 0.013 of a 10-bit
  code** inside the display's reachable range — below the panel's own run-to-run
  repeatability — so this is a correctness and robustness change, not a visible fix. The one
  behavioural change is at the top end: beyond the measured peak the response is
  many-to-one, so every target above the peak now maps to the peak's code value.
- Deleted the dead `lut.generate_mhc2_lut_from_measure_data()`; `tools/` gained
  `verify_lut_inverse.py`; small `i18n` additions; main window default height 1000 → 1050 px.

### Repository and packaging

- The repository is now organised as tagged releases: this is **`v2026.09.22`**, the previous
  release is **`v2026.09.02`**.
- New packaging workflow (`.github/workflows/release.yml`): pushing a `v*` tag builds
  `rwhc-<tag>.zip` from the tagged tree and attaches it — plus a `.sha256` — to the GitHub
  Release. The archive is verified before publishing (every entry re-read and compared with
  the tag, required files present, no caches/virtualenvs/logs/archives) and its content is
  reproducible because packaging always reads the tag, never the working tree.
- Dropped the `__pycache__/*.pyc` files that had been committed by mistake, and fixed the
  README links that pointed at a repository name (`rwhc-v2026.09.02`) which no longer resolves.

## Scope and caveats

- Targets **Windows 11** with **Python 3.14**, and needs a supported colorimeter
  (ArgyllCMS-based) for live measurement — the self-check tools above run without hardware.
- `A2B0`/`B2A0` accuracy from the synthetic self-test at 33³: `A2B0` mean interpolation error
  ≈ 0.005% (max < 1%, worst case right at the PCS ceiling); `B2A0` is exact for unclipped
  colours (median closed-loop error ≈ 0.002%). Inside the clipped highlight region the inverse
  is inherently many-to-one — a property of the relative-colorimetry PCS, documented in both
  READMEs.
- The maintainer is not a colour-science professional and this release is largely
  AI-assisted and manually reviewed. Please review before relying on it.

## 中文摘要

- **新增 CLUT（多维 LUT）ICC 输出**（`clut_icc.py`）：可选 17/25/33/37/45/65（默认 33）网格，写入标准
  ICC v4 `A2B0`（设备 PQ 码值 → PCS）与 `B2A0`（`mft2`）标签；矩阵标签与 `MHC2` 完全保持不变，默认关闭，
  且只使用本次校色已测得的数据，不需要额外测量。
- **历史颜色数据**（`color_history.py`）：与既有「历史灰阶数据」同理，可复用过去一次校色的颜色测量
  （从 `hc.log` 解析，测量完整才会出现在列表里），新增下拉框与「刷新」按钮。
- **没有光度计时也能校色**：两个历史数据下拉框都选好后，不再启动仪器、`dogegen` 和「放置色度计」提示框，
  也跳过无意义的事后色域复测；「测量色彩准确度」会明确提示需要真实仪器，而不是抛异常。
- **修复「保存 ICC 文件」卡死**：CLUT 的 `B2A0` 反向求解改到工作线程，保存 33³ 时主线程最多阻塞
  **0.21 秒**（原来约 37 秒），且生成的 ICC 与原来逐字节一致（sha256 相同）。
- **CLUT 反向求解快约 1.6 倍**：最近邻第一步改用等价的范数展开（一次 BLAS 矩阵乘），33³ 时不再产生
  约 8.6 GB 量级的临时数组；输出逐位不变（`max|Δ| = 1.1e-16`），并修掉了一个只在特定调用规模下才成立的
  形状 bug。
- **MHC2 一维 LUT 改为实测 PQ 响应的真正反函数**（最近邻反查 → `np.interp` 分段线性逆插值）。如实说明
  范围：`hc.log` 中 15 次真实灰阶 run 实测，新旧 LUT 差异为**平均 0.006、最大 0.013 个 10bit 码值**，低于
  面板自身重复性，属正确性/健壮性改进而非可见修复；唯一行为变化在顶端——峰值之后响应多对一，高于实测
  峰值的目标一律取峰值处的码值。
- **仓库与发布**：本仓库改为按标签发布，本次为 **`v2026.09.22`**（上一版 **`v2026.09.02`**）；新增打包
  工作流（`.github/workflows/release.yml`），推送 `v*` 标签即从该标签的代码树打包 `rwhc-<tag>.zip` 并附上
  `.sha256` 到 GitHub Release，打包前会逐条校验内容；同时清理了误提交的 `__pycache__`、修正了失效的
  README 链接。
- **注意**：目标是 Windows 11 + Python 3.14，实机测量需要支持的色度计；维护者并非色彩科学专业，本版本
  大量由 AI 辅助完成并人工核对，使用前请自行审查。

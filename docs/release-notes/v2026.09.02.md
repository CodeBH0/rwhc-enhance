# rwhc v2026.09.02

Released 2026-09-02 (tagged during the 2026-09-22 repository tidy-up, from the same tree) · [full changelog](https://github.com/CodeBH0/rwhc-enhance/blob/master/CHANGELOG.md) · [中文更新日志](https://github.com/CodeBH0/rwhc-enhance/blob/master/CHANGELOG_zh.md) · next release: [`v2026.09.22`](https://github.com/CodeBH0/rwhc-enhance/releases/tag/v2026.09.22)

Windows 11 HDR calibration tool. Unzip the attached `rwhc-v2026.09.02.zip`, then
`pip install -r requirements.txt` and `python app.py` — see the
[README](https://github.com/CodeBH0/rwhc-enhance/blob/master/README.md) for the full setup.

This is the first tagged release of this repository: the 2026-09-02 state of the maintained
fork (24-colour-card generation). The CLUT output, historical colour data and the
no-colorimeter path arrive in `v2026.09.22`.

## Highlights

### Added

- **24-colour industry-standard test card** (X-Rite ColorChecker Classic, a.k.a. Macbeth
  ColorChecker). The "Color sample set" dropdown now has four tiers —
  `sRGB(12)` / `sRGB(12)+DisplayP3(7)` / `sRGB(24)` / `sRGB(24)+DisplayP3(7)` — with the
  default unchanged (12). The 24-colour card uses each patch's real chromaticity and relative
  luminance, scaled to the SDR paper-white anchor, so the fit no longer relies only on the
  brightest colours.
- **Historical gray data** (`gray_history.py`): when calibrating several colour temperatures
  on the same display, the PQ grayscale curve does not need to be re-measured every time — the
  panel's native response does not depend on the target white point, only the white-point
  adaptation does. Pick a past complete measurement in the new "Historical gray data"
  dropdown (labelled with its measurement end time) and the PQ curve step reuses it; a
  "Refresh" button reloads the list, which also refreshes automatically after a calibration.

### Fixed / improved

- **SDR paper white is read from the Windows system setting** instead of being hard-coded, and
  used as the brightness anchor for the white test patch and the calibration test sets.
  Source: `DISPLAYCONFIG_SDR_WHITE_LEVEL` (the "SDR content brightness" slider), converted with
  `nits = raw / 1000 × 80` — in slider terms `nits = slider × 8`, so slider 20 → 160 nits. The
  white test patch code is recomputed at the start of every calibration
  (`code = round(pq_oetf(paper_white) × 1023)`); it falls back to 200 nits if the system value
  cannot be read. The value is read **once at application start**, so set the slider to your
  actual viewing brightness before launching the app.
- The fitted correction matrix is no longer written into the `MHC2` matrix (Windows multiplies
  content XYZ by that matrix directly, which made warm colours undersaturated). The profile
  keeps an identity matrix and lets the measured primaries + 1D LUT do the gamut mapping.
- `rXYZ`/`gXYZ`/`bXYZ`/`wtpt` are jointly scaled to the white point (ICC convention,
  r+g+b = wtpt) and the TRC is written as the sRGB EOTF, so profiles are ICC-conformant.
- Fixed a wexpect 4.0.0 + virtualenv deadlock that froze the GUI during calibration (spawn now
  uses the real base interpreter and has a timeout; leftover helpers are cleaned up).
- Verified on the maintainer's display (FFALCON R27U81): average ΔE **1.16** / max **5.52** on
  the 12-colour card.

## Scope and caveats

- Targets **Windows 11** with **Python 3.14**, and needs a supported colorimeter
  (ArgyllCMS-based) — calibration always measures on the display in this version.
- It is recommended to install the vendored wexpect copy rather than the PyPI one:
  `pip install --force-reinstall --no-deps ./wexpect-4.0.0/` (the PyPI build imports
  `pkg_resources`, which setuptools ≥ 81 no longer ships).
- The maintainer is not a colour-science professional and this release is largely
  AI-assisted and manually reviewed. Please review before relying on it.

## 中文摘要

- **新增 24 色行业标准色卡**（X-Rite ColorChecker Classic / Macbeth）：「色彩采样集」下拉框现有 4 挡
  `sRGB(12)` / `sRGB(12)+DisplayP3(7)` / `sRGB(24)` / `sRGB(24)+DisplayP3(7)`，默认仍为 12 色；24 色
  使用每块色块的真实色度与相对亮度并锚定到 SDR 纸白，拟合不再只依赖最亮的几块颜色。
- **新增「历史灰阶数据」**：同一台显示器校多个色温时无需重复测量 PQ 灰阶曲线（面板原生响应不随目标白点
  变化），在下拉框里选择过去一次完整测量即可复用。
- **SDR 纸白改为读取 Windows 系统设置**（`DISPLAYCONFIG_SDR_WHITE_LEVEL`，`nits = raw/1000 × 80`，
  即滑块 20 → 160 nits），作为白块与测试集的亮度锚点；白块码值每次校色重新计算，读不到时回落 200 nits；
  该值仅在启动时读取一次。
- **ICC 修正**：拟合出的修正矩阵不再写入 `MHC2` 矩阵；`rXYZ`/`gXYZ`/`bXYZ`/`wtpt` 按白点联合归一化
  （r+g+b = wtpt），TRC 写为 sRGB EOTF，配置文件符合 ICC 规范。
- **修复** wexpect 4.0.0 + 虚拟环境导致的校色过程中界面卡死。
- 维护者实测（FFALCON R27U81）：12 色卡平均 ΔE **1.16** / 最大 **5.52**。
- **注意**：目标平台为 Windows 11 + Python 3.14，需要支持的色度计；建议安装仓库内自带的 wexpect
  （`pip install --force-reinstall --no-deps ./wexpect-4.0.0/`）。

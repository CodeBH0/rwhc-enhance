# 色彩算法参考手册

一套自包含的显示色彩计算规范：公式、精确常数、参考数据表、以及从零开始的数学入门。

面向需要**在自有代码里实现色彩计算**的工程师。全部内容不依赖任何外部库或专有实现，
可直接照抄公式，或直接使用 `reference/` 下的实现。

## 快速开始

```python
import sys
sys.path.insert(0, "reference")
import color_math as C

# 坐标变换
C.xyz_to_xy(0.9505, 1.0, 1.0890)          # -> (0.3127159..., 0.3290014...)
C.xyz_to_lab(0.2, 0.5, 0.9, 0.9505, 1.0, 1.0890)
                                            # -> Lab + C* + h

# 色温
C.xy_to_cct(0.3127, 0.3290)               # -> 约 6459 K
C.cct_to_xy(6500.0)                       # -> 色度坐标

# 传递函数
C.srgb_eotf(0.5)                          # -> 0.2140411...
C.pq_eotf(0.5)                            # -> PQ 绝对亮度

# 色差
C.delta_e_2000((50, 2.6772, -79.7751), (50, 0.0, -82.7485))   # -> 2.0425

# 色域矩阵
C.primaries_to_matrix(((0.64,0.33),(0.30,0.60),(0.15,0.06)), (0.3127,0.3290))
```

## 使用须知

### 关于数值一致性

手册中少数常数以**近似值**给出（例如 $\varepsilon = 0.008856$ 而非精确的 $(6/29)^3$）。
这是刻意的：某些既有系统的历史实现采用了这些近似值，若你要与之**逐位一致**，
必须沿用同一组近似；若只要求**视觉一致**，用精确值更好。

每篇文档的"自检用例"一节给出了期望值，可用于验证实现。若你的结果与期望**只差末位**，
通常是表达式求值顺序不同（例如把 `a/b/c` 写成 `a/(b*c)`）——这在浮点下不等价。

### 关于错误处理

全手册统一约定：**遇到非法输入（除零、参考白点分量为 0、参数越界）时，
返回错误指示并且不修改输出变量**。

不要用"返回 0"来表示失败——调用方无法与"成功且结果为 0"区分。

### 关于色相角

色相角 $h$ 存在**两套并行的约定**（`01` §5.3）：

| 约定 | 值域 |
|---|---|
| A（CIE 标准）| $(-\pi, \pi]$ |
| B（工程变体）| $(-\pi/2, \pi/2]$ |

两者在第一、三象限相同，第二、四象限差 $\pi$。
**跨系统交换数据前务必确认用的是哪套**，否则会出现"颜色看起来没错但色相数值差 180°"的诡异现象。

### 关于参考白点

Lab / Luv 的计算**必须**指定参考白点，且参与比较的所有颜色必须用**同一个**白点换算。
不同白点下的 $a^*, b^*$ 不可直接比较——这是最常见的错误来源之一。

## 数据来源与适用范围

本手册的公式均取自公开的色彩科学标准体系（CIE、ITU-R、SMPTE 等），
常数与数据表按标准定义给出。它描述的是**通用算法**，与任何特定设备或软件无关。

`data/` 中的数值表可直接用于生产；若你的应用有更严格的溯源要求，
应自行对照相应标准的原始出版物复核。
